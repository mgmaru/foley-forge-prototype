# FoleyForge

> ステータス: 設計フェーズ（プロトタイプ）
> プロジェクト名は仮称です。今後変更の可能性があります。

作画したイラストやアニメーションシーンに合うSE（効果音）を、シーンごとにピンポイントで生成する個人用の制作支援ツールです。フリー素材サイトでは見つけにくい「そのシーンのための音」を、生成AIによってその場で作り出すことを目的としています。

## 特徴

- **日本語の曖昧なシーン記述やイラストから音を生成** — テキストと画像（オプション）を入力に、マルチモーダルLLMがシーンを解釈します。
- **耳で選ぶ体験** — 「指示追従性 vs 音響的美しさ」のトレードオフを数値で調整させるのではなく、異なる特性を持つ複数候補を生成し、ユーザは耳で選びます。
- **技術的パラメータの隠蔽** — CFG値や推論ステップ数などの調整はバックエンドが最適化し、ユーザに見せません。判断するのは「シーン記述」と「生成音の選択」だけです。
- **ファインチューニングなしの品質向上** — Best-of-N生成＋複数指標によるリランキング、構造化データを介したプロンプト生成、戦略別パラメータ最適化を統合します。

## アーキテクチャ

バックエンド中心の設計です。アプリの本質的な価値はバックエンドにあり、フロントエンドはそれを使いやすくするための殻と位置付けています。

```
┌─────────────────────────────────────────────┐
│  フロントエンド（Tauri + React/TypeScript） │
│  シーン記述入力 / 画像アップロード /         │
│  音タイプ・長さ・バリエーション数の選択 /    │
│  候補の試聴と選択                            │
└─────────────────────────────────────────────┘
                    ↓ ↑
┌─────────────────────────────────────────────┐
│              バックエンド（Python）          │
│                                             │
│  1. ユーザ入力受付                           │
│  2. 構造化データ生成（マルチモーダルLLM）    │
│  3. プロンプト生成戦略の決定（3戦略）        │
│  4. パラメータ決定（CFG・ステップ数・シード）│
│  5. 並列生成（Stable Audio Open）            │
│  6. 評価とフィルタリング（CLAP / PQスコア）  │
│  7. 候補選別（戦略別に上位を配分）           │
│  8. ユーザへの提示と構造化ログ永続化         │
└─────────────────────────────────────────────┘
```

### 技術スタック

| レイヤー | 技術 | 採用理由 |
|---------|------|---------|
| フロントエンド | Tauri + React/TypeScript | ローカルファイルアクセス、既存知見の流用 |
| バックエンド | Python | 拡散モデル・CLAP等のエコシステムが充実 |
| 音声生成モデル | Stable Audio Open | アニメ寄り環境音に強い、47秒対応、OSS |
| LLM（マルチモーダル） | Claude API | 画像理解の品質が高い |
| LLM（プロンプト変換） | Ollama（ローカル） | コスト0、自分用なので使い倒せる |
| 品質評価 | LAION-CLAP, PAMスコア | 指示追従性と音響品質の評価 |

## 品質向上戦略

ファインチューニングなしで品質を上げるための、本アプリの肝となる手法です。

1. **LLMによるプロンプト augmentation** — 構造化データを介してFreesound風のプロンプトに変換し、Stable Audio Openの訓練データ分布に近づけます。
2. **戦略別のパラメータ最適化** — CFG値の研究知見（CLAPスコアのピークはCFG=3.5前後、音響品質が安定するのはCFG=4〜6）を活用し、戦略ごとにスイートスポット内で使い分けます。
3. **Best-of-N + リランキング** — 複数候補を生成し、CLAPとPQの両指標でフィルタ・選別します（DCASE2023優勝システムも同様の手法）。
4. **多様性のある候補提示** — 3つの戦略（指示追従寄り / バランス / 音響美寄り）から候補を混ぜて提示し、トレードオフを耳での選択として吸収します。

## 構造化データ

構造化データはアプリの中核データ構造であり、シーン記述・画像をLLMが解釈した結果を表現します。プロンプト品質の底上げ、戦略の差し替え容易性、デバッグ可能性、実験基盤、ドメイン知識の蓄積場所という役割を担います。含める情報領域は以下です。

- シーン全体のコンテキスト（場所、雰囲気、時間帯、空間感）
- 主要な音源（対象、動作、素材、強度）
- 環境音・背景要素（背景音、リバーブ、密度）
- 音響特性のヒント（周波数強調、ダイナミックレンジ、品質キーワード）
- 避けたい要素（ネガティブプロンプト用）

## データの永続化

実験的調整を可能にするため、全セッションのデータを構造化ログとして保存します。ユーザ入力、構造化データ、生成プロンプトバリアント、生成パラメータ、生成結果、各候補のCLAP/PQスコア、最終選別結果、ユーザのアクションを蓄積し、継続的な品質改善の基盤とします。

## 用語

| 用語 | 説明 |
|------|------|
| SE | Sound Effect（効果音） |
| フォーリー音 | 映像作品で人や物の動作に合わせて作る効果音 |
| Stable Audio Open | Stability AI製のOSS音声生成モデル |
| CFGスケール | Classifier-Free Guidance、プロンプト追従度を制御するパラメータ |
| CLAP | Contrastive Language-Audio Pretraining、音声とテキストの類似度を測るモデル |
| PQスコア | Perceptual Quality、知覚的な音響品質スコア |
| PAMスコア | Prompting Audio-Language Modelsで提案されたCLAPベースの品質指標 |
| Best-of-N | 複数生成して最良のものを選ぶ手法 |
| Freesound | 音声共有プラットフォーム、Stable Audioの訓練データに含まれる |
